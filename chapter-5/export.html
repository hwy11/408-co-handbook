Browser-side ZIP Export

导出项目源文件

在浏览器里直接拼装 ZIP —— 不走后端、不调命令行。使用 store（无压缩）模式，自己算 CRC32、手写 Local File Header / Central Directory / EOCD，最后用 Blob 触发下载。适合小中型源码打包和受限沙盒下的迁移交付。

3 · 工作原理

  1. 把清单里的每个路径拼接 BASE URL，用 fetch() 读成 ArrayBuffer。
  2. 对每个字节流算 CRC32（标准 PKZIP 多项式 0xEDB88320，查表法）。
  3. 为每个文件写一份 Local File Header（签名 0x04034b50、版本 20、compression=0、CRC、长度、文件名 UTF-8）+ 原始字节。
  4. 追加一份 Central Directory（签名 0x02014b50），汇总所有文件的元数据与偏移。
  5. 最后写入 End of Central Directory（签名 0x06054b50），指向 CD 起点和总大小。
  6. 所有字节拼成 Uint8Array → new Blob([...], {type:"application/zip"}) → <a download> 触发保存。
i
为什么用 store（stored）模式？ 因为 ZIP 的压缩算法 deflate 手写量大（LZ77 + 哈夫曼），而 store 模式只是"原样装进 ZIP 容器"，规范极简。代价是文件体积等于源文件之和，对源码类文本可接受；若要真正压缩，引入 pako 或 CompressionStream 即可。
!
限制：不支持 ZIP64（单文件 > 4 GB 或总文件数 > 65535）；不处理加密、跨域资源（受 CORS 限制）、及 file:// 协议下的 fetch()（需经本地服务器或托管环境）。
